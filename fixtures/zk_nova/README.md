# zk_nova reference vectors (nova-snark 0.76.0, Pallas/Vesta, ppsnark + IPA)

Oracle data for a zero-dependency Rust verifier of
`nova_snark::nova::CompressedSNARK<PallasEngine, VestaEngine, C, S1, S2>` with
`S1 = spartan::ppsnark::RelaxedR1CSSNARK<PallasEngine, provider::ipa_pc::EvaluationEngine<PallasEngine>>`
and `S2` the same over Vesta. This is the **preprocessing** SNARK (`spartan::ppsnark`), not
`spartan::snark` (which `nova-header-chain` uses today).

Generated by `integrations/tradelayer-nova-vectors` of
[zk-rusto-no-bitcoino](https://github.com/patrickdugan/zk-rusto-no-bitcoino/tree/20b9e1f/integrations/tradelayer-nova-vectors)
(commit 20b9e1f). It links nova-snark, so it lives outside this zero-crate repository
(`scripts/check_rust_supply_chain.py`). It is pinned to rustc 1.99.0, with its Cargo.lock copied from
`nova-header-chain`: nova-snark 0.76.0, halo2curves 0.9.0, ff 0.13.1, sha3 0.10.9, sha2 0.10.9,
bincode 1.3.3. All randomness is ChaCha20 seeded from
`SHA-256("nova-vectors-0.76.0-seed-2026-11" || tag)`. The vectors are reproducible; the proofs are
not, because Spartan blinding randomises them.

Regenerate: in that directory run `cargo build --release --locked`, then `gen_basic`, `gen_core`,
`gen_proofs`, `gen_trace <name>...` and `gen_nhc1 <start> <k> <steps>`, with `NOVA_VEC_OUT` set to
this directory and `RAYON_NUM_THREADS=8`. `gen_nhc1` also needs `NHC1_FIXTURES`, which is
`integrations/nova-header-chain/fixtures` on that repository's `feat/cheap-btc-proofs` branch.

## Conventions

* Plain text, one record per line, tab separated, lines starting with `#` are comments. Each `.tsv` file
  begins with comment lines that define every record type; this README summarises them.
* Hex is lowercase. A **field element** is 64 hex chars = the 32-byte little-endian canonical
  `PrimeField::to_repr`. `fp` = Pallas base field = Vesta scalar field (modulus `0x40000000000000000000000000000000224698fc094cf91b992d30ed00000001`);
  `fq` = Pallas scalar field = Vesta base field (modulus `0x40000000000000000000000000000000224698fc0994a8dd8c46eb2100000001`).
* A **point** token is `inf` or `<x hex>:<y hex>` (affine). Both curves are `y^2 = x^3 + 5`.
* `none` = the operation returns `None`/`CtOption::none`.
* Binary blobs (vk, proofs) are `*.hex` files holding a single hex line.

## Serialization facts (bincode 1.3, `bincode::serialize`: fixint, little-endian, no limit)

nova-snark derives `Serialize`/`Deserialize` (serde) on all key and proof types; nothing is hand-encoded
except the Keccak transcript. (nova's own `digest.rs` uses bincode 2 with the `legacy()` config, which is byte-identical to bincode 1.)

* `usize`/`u64` = 8 bytes LE. `Vec<T>` = `u64` count then the elements, no padding. Fixed arrays and tuples = no prefix.
  `PhantomData` and `#[serde(skip)]` fields (`digest` caches) write nothing. No enum appears in vk or proof.
* **Field element** (`Fp`, `Fq`): `serde_arrays` of the 32-byte little-endian `to_repr`; decoding rejects values >= modulus.
* **Group element** (`Pallas`/`Vesta` projective *and* `PallasAffine`/`VestaAffine`): both serialize through
  `GroupEncoding::to_bytes` as a **32-byte array with no length prefix**: x little-endian, bit 7 of byte 31 = parity of y;
  the identity is 32 zero bytes. Decoding: x = 0 (with either sign bit) decodes to the identity, a non-canonical x or an x
  with no square root is an error. (`serde_points.tsv` shows affine and projective bytes are identical.)
* `Commitment<E>` (`provider::pedersen`) = `struct { comm: E::GE }` => exactly the 32-byte compressed point.
* `CommitmentKey<E>` = `{ ck: Vec<Affine>, h: Affine }` => `u64 count`, `count * 32`, then `h` (32). `DerandKey` = `{ h }` = 32 bytes.
* `RelaxedR1CSInstance<E>` = `comm_W (32) | comm_E (32) | X: Vec<Scalar> (8 + 32*len) | u (32)` (len = 2 in a valid proof).
  `R1CSInstance<E>` = `comm_W | X`. `NIFS`/`NIFSRelaxed` = `comm_T` (32).
* `SumcheckProof` = `Vec<CompressedUniPoly>`, `CompressedUniPoly` = `Vec<Scalar>` of the coefficients without the linear term
  (cubic: `[c0, c2, c3]`): `8 + rounds * (8 + 3*32)` bytes.
* The `ppsnark` proof (`RelaxedR1CSSNARK`), field order: 6 commitments (`comm_L_row, comm_L_col, comm_t_plus_r_inv_row,
  comm_w_plus_r_inv_row, comm_t_plus_r_inv_col, comm_w_plus_r_inv_col`), `sc_outer`, 4 scalars (`eval_Az, eval_Bz, eval_Cz, eval_E` at `r_outer`),
  `sc_inner_batched`, 15 scalars (`eval_E, eval_L_row, eval_L_col, eval_val_A, eval_val_B, eval_val_C, eval_W, eval_t_plus_r_inv_row,
  eval_row, eval_w_plus_r_inv_row, eval_ts_row, eval_t_plus_r_inv_col, eval_col, eval_w_plus_r_inv_col, eval_ts_col`),
  then the IPA argument `{ L_vec: Vec<Commitment>, R_vec: Vec<Commitment>, a_hat: Scalar }`.
* `CompressedSNARK` field order: `r_U_secondary, ri_secondary, l_u_secondary (R1CSInstance), nifs_Uf_secondary,
  l_ur_secondary (Relaxed), nifs_Un_secondary, r_U_primary, ri_primary, l_ur_primary, nifs_Un_primary,
  wit_blind_r_Wn_primary, err_blind_r_Wn_primary (Fq), wit_blind_r_Wn_secondary, err_blind_r_Wn_secondary (Fp),
  snark_primary, snark_secondary, zn: Vec<Fq>`. Secondary objects are over Vesta (scalars in `fp`), primary over Pallas (scalars in `fq`).
  Exact offsets: the `proof_region` records of each `.meta.tsv`.
* `VerifierKey` field order: `F_arity u64 | ro_consts_primary | ro_consts_secondary | pp_digest (Fq) | vk_primary | vk_secondary | dk_primary (32) | dk_secondary (32)`.
  `vk_x` = `num_cons u64 | num_vars u64 | vk_ee { ck_v: CommitmentKey, ck_s: CommitmentKey } | S_comm { N u64, comm_row, comm_col,
  comm_val_A, comm_val_B, comm_val_C, comm_ts_row, comm_ts_col (7 x 32) }`.
  `ro_consts_primary` is `PoseidonConstantsCircuit<fp>` and `ro_consts_secondary` is `<fq>`, 271 800 bytes each (see `poseidon_params.tsv`;
  they are the default constants, so a verifier can ignore them and use the generated ones).
  `ck_v` is the whole R1CS commitment key (N generators), `ck_s` is the IPA scale key (1 generator).
* **The vk is dominated by generators** and the generator lists are deterministic functions of the labels (below). `vk_nogens.hex`
  removes them: the removed ranges are the `vk_removed_generator_range` records (`u64 count` + `32 * count` bytes each, `h` stays in place).
  `gen_trace` rebuilds the full vk from `vk_nogens.hex` plus `from_label` and verifies the proof with it.

## Labels, generators, hash-to-curve

Found by grepping nova-snark 0.76.0 `src/`:

* `b"ck"`: `r1cs/mod.rs` `commitment_key` -> `E::CE::setup(b"ck", max_size)` -> `E::GE::from_label(b"ck", max_size.next_power_of_two() + 1)`.
  Point 0 is `h` (blinding generator, also the `DerandKey`); points 1.. are the `ck` generators. For ppsnark the `max_size`
  is at least `ck_floor` = number of nonzeros of A+B+C (`spartan/ppsnark.rs`), so the generator count is
  `N = max(nnz_total, 2*m, m).next_power_of_two()` where `m = max(num_cons, num_vars).next_power_of_two()` (this is also `S_comm.N`).
* `b"ipa"`: `provider/ipa_pc.rs` `E::CE::setup(b"ipa", 1)` -> `from_label(b"ipa", 2)`: `h`, then the single `ck_s` generator.
* `from_label(label, n)`: `SHAKE256(label)` read as a stream, 32 bytes per point `i`, point = `Point::hash_to_curve("from_uniform_bytes")(32 bytes)`.
* Hash to curve (halo2curves 0.9.0 `hash_to_curve.rs`): `DST = "from_uniform_bytes" || "pallas:SHA-256_SVDW_RO_"` (resp. `vesta:`), `expand_message_xmd(SHA-256, 96 bytes)`,
  two field elements from 48-byte chunks each **reversed** (read big-endian) via `from_uniform_bytes`, Shallue-van de Woestijne (RFC 9380 6.6.1, Z = -13), sum of the two images. All intermediate values are in `hash_to_curve.tsv`.
* n values with their SHA-256 over the concatenated 32-byte compressed encodings: n = 2^10+1 (1025), 2^14+1 (16385), 2^17+1 (131073, the cubic proofs),
  2^20+1 (1048577, NHC1 k=1) in `generators.tsv`; the n of the other proofs is in their `meta` (`from_label_n_primary_ck`).

## Transcript and RO conventions

* `Keccak256Transcript<E>` (`provider/keccak.rs`): fully specified in the `transcript.tsv` header (state = 64 bytes = `Keccak256(prefix||input||0x00) || Keccak256(prefix||input||0x01)`,
  `"NoTR"`/`"NoDS"` tags, round counter u64 LE; challenge = `Scalar::from_uniform_bytes(state)`).
* `TranscriptReprTrait` encodings: scalar = 32 B LE; `&[T]` = concatenation; **`Commitment` = x (32 LE) || y (32 LE) || infinity byte** (NOT the 32-byte compressed form);
  `UniPoly` = compressed coefficients (without the linear term); `RelaxedR1CSInstance` = `comm_W || comm_E || u || X...`; the vk is absorbed as its 32-byte digest scalar.
* Poseidon RO (`provider/poseidon.rs`): `PoseidonRO<Base>` with `ROMode::Wide` (arity 24, width 25, rf = 8, rp = 59, alpha 5), constants fully deterministic
  (Cauchy MDS `1/(i+t+j)`, Grain LFSR round constants; generator inputs in `poseidon_params.tsv`), SAFE-API capacity tag, `squeeze(num_bits, start_with_one)` keeps
  the first `num_bits` little-endian bits of the raw hash. After a squeeze the RO state is `[raw]`. `CompressedSNARK::verify` creates a fresh RO each time.
* Absorbing into the RO (`AbsorbInROTrait`): `Commitment` = `x, y, is_infinity` as base-field elements; a `RelaxedR1CSInstance` absorbs `comm_W, comm_E, u (as base), then
  each X[i] as 4 little-endian 64-bit limbs`; an `R1CSInstance` absorbs `comm_W` then each `X[i]` as one base element. `NUM_CHALLENGE_BITS = 128`, `NUM_HASH_BITS = 250` (`constants.rs`).
  The complete event list for a real verification is in `<name>.trace.tsv`.
* `DigestComputer` (`digest.rs`): `digest = first 250 bits (little-endian bit order inside each byte) of SHA3-256(bincode1(value))` as a field element.
  `pp_digest` is that for `PublicParams` (it is stored in the vk; not recomputable without the R1CS shape). The Spartan verifier key digest is that value over
  `vk_primary` (resp. `vk_secondary`) **including the generator lists**; it is the scalar absorbed under label `vk` in the Spartan transcript, in `fq` for the primary and `fp` for the secondary.
  Because it is a pure function of the vk it can be pinned at registration time instead of being recomputed (hashing 270 MB for NHC1 k=10).
  An independent SHA3 computation equals nova's digest on every run (asserted by the generator).

## CompressedSNARK::verify as exercised by the traces

1. `hasher = E2::RO`: absorb `pp_digest (Fq)`, `num_steps`, `z0..`, `zn..`, `r_U_secondary` (RO absorb form), `ri_primary`; squeeze 250 bits -> must equal `l_u_secondary.X[0]` (as Fq from Fp bytes);
   `hasher2 = E1::RO`: absorb `scalar_as_base(pp_digest)`, `num_steps`, `0`, `0`, `r_U_primary`, `ri_secondary`; squeeze 250 bits -> must equal `l_u_secondary.X[1]`.
2. `nifs_Uf_secondary.verify` (RO fq, 128 bits), `nifs_Un_secondary.verify` (RO fq), `nifs_Un_primary.verify` (RO fp): fold the instances with the 128-bit challenge.
3. Derandomize the two folded instances with `dk` and the blinds, then run the two ppsnark verifiers (labels in order, from the trace): `vk, U`, `t` x log2(num_cons), outer sumcheck (`p`/`c`), `e`, `p` x (log2 N - log2 num_cons),
   `e`, `c, g, r`, `l`, `r` x log2 N, `r`, inner sumcheck (`p`/`c`), `e`, `c`, IPA: dom_sep `IPA`, `U`, `r`, then `L`,`R`,`r` per round.

## Size formulas (exact, asserted on every generated proof)

```
proof_bytes = 536 + 400 + 128 + S(Ro_p, Ri_p, Ri_p) + S(Ro_s, Ri_s, Ri_s) + 8 + 32 * arity
S(Ro, Ri, K) = 864 + 104 * (Ro + Ri) + 64 * K          Ro = log2(padded num_cons), Ri = K = log2(N)
vk_bytes     = 8 + 2*271800 + 32 + (360 + 32*N_p) + (360 + 32*N_s) + 64
```

## Reference results

Machine: Ryzen AI 9 365 laptop, Windows, CPU only, `RAYON_NUM_THREADS=8`. Every proof below was verified by nova's own
`CompressedSNARK::verify` with the returned `zn` equal to the native computation, and every corrupted/mismatched variant
listed in its `.meta.tsv` (`corrupt*`, `wrong_num_steps`, `wrong_z0`, truncation) is rejected.

* The secondary (Vesta) shape is independent of the step circuit: 10 349 constraints, N = 2^17, and its vk part / digest
  (`vk_secondary_digest` = `445f7ef1...18d01`) are identical in all sets. Primary vk digests: cubic `cda5f251...f3e02`, NHC1 k=1 `d4f73ccf...30d01`.
* `nhc1_ppsnark_k1x10` proves the 10 headers 959985..959994 as ten fold steps of one header each (the NHC1 circuit with `k = 1`, checkpoint 959984 from
  nova-header-chain's fixtures, `steps = 10`). Timings: pp setup 74 s (almost all of it hashing 2^20+2^17 generators to the curve), 10 folds 11 s, compressed setup 8.5 s,
  compressed prove 199 s, nova verify 4.5 s, peak working set 2.1 GiB.
* NHC1 as a single 10-header step (`k = 10`, the shape of the pinned NHC1 vk) was run to completion of nova's prove and verify but its vectors were not dumped:
  pp setup 449 s (peak 2.9 GiB while hashing 2^23 generators), fold 1 s, compressed setup 39 s, **compressed prove 1 490 s**, **peak working set 14 177 MiB (13.8 GiB)**,
  nova verify about 51 s, verified proof at 2 032 s wall. The generator's own post-processing (re-decoding the 2^23-point vk) was cut off by the 45-minute watchdog at 2 701 s.
  Sizes for this shape come from the exact formulas above.
* With the preprocessing SNARK the commitment key must cover the nonzeros of A+B+C, so N is 2^23 for k=10 versus 2^17 for the plain cubic circuit; the vk is 97 % generators
  (268 MB for k=10) while the proof stays 11-14 KB. A verifier that derives the generators from `from_label` needs only the 544 328-byte `vk_nogens` part.
  Verification cost is dominated by one MSM of size N per curve (the IPA `ck_hat = commit(ck, s)` with the length-N tensor vector `s`); the other MSMs are O(log N).
* `cubic_*` and `nhc1_*` `.vk_nogens.hex` are byte-identical across sets except for the per-circuit fields (num_cons, num_vars, N, S_comm commitments, pp_digest): the Poseidon constants (2 x 271 800 bytes) dominate.

## Checks done by the generators (all assertions passed)

* fields/curves/serde: every `from_repr`, `to_bytes`/`from_bytes`, bincode round trip and the group law identities are re-checked against the library while writing; `order * G = identity`.
* hash-to-curve: the local copy of halo2curves' pipeline (`expand_message_xmd`, `svdw`) reproduces `Point::hash_to_curve("from_uniform_bytes")` for all 108 inputs; the xmd output matches RFC 9380 K.1.
* transcript: an independent Keccak implementation of the transcript equals `Keccak256Transcript` (challenge and 64-byte state) in all 80 sessions.
* Poseidon: a plain permutation + SAFE sponge written from the raw constants equals `PoseidonRO` on every session in poseidon.tsv (136 per field, wide and narrow).
* proofs: nova's `verify` accepts, the vk/proof mirror structs re-encode to the identical bytes, the vk generator lists equal `from_label`, the independent SHA3 vk digest equals nova's,
  the size formulas equal the measured sizes, and all corrupted variants are rejected; `gen_trace` rebuilds the full vk from `vk_nogens.hex` + `from_label` (hash equal) and re-verifies under a recording engine.
