# TLSW3 integration design

Mount the new source include, its integration test, the independent command-pin script and these two documents. Apply `prepare.py:apply_source` to the current `src/source_contract_replay.rs`: it inserts one include immediately after the existing TLSW2 include. The work-only copied replay/old witness files are an isolated-test harness and must not replace repository files. The include adds a separate API and no runtime-policy or business-logic change.

The implementation reuses the existing `SourceContractReplay`, `SourceContractCommand` diagnostic codec, bounded frame codecs, state commitment and one actual `SourceContractRuntime`. It holds only the before checkpoint and original suffix; no second registry, balance ledger, state interpreter or claimed poststate decoder is introduced. Producing a witness does not mutate the caller. Verification reconstructs the actual owner and returns that owner plus the exact suffix receipts.

The new scope and policy gates are explicit. Existing TLSW1/TLSW2 code remains byte-identical, including TLSW2's V8 `WrongPolicy` refusal. Future runtime owner availability cannot automatically expand TLSW3 to V9. The Main scope reflects only the callable entry that the runtime implements; source extraction completeness, authentication and daemon startup remain independent obligations.

Both endpoint heads/state commitments and entry profiles are mandatory external pins. The descriptor, exact policy, numeric/dependency boundary and command digest distinguish the execution graph. Required pins reject replay-history substitution even if an attacker repairs all envelope checksums. The separate drained endpoint rule prevents a hidden pending height/Tally continuation from being mistaken for completed work. Source throws retain actual prefixes; local unsupported-domain suffixes cannot be issued as source-execution witnesses.

The test harness imports only input/bootstrap state at original source resets. It reuses the unchanged source generators and their original financial/dependency observations. A verified replay replaces a direct replay only after exact equality with a separately advanced actual owner; the original source output assertions then check that owner. Expected source poststates are comparison evidence and never become witness inputs.

The immutable cached runtime is pinned by SHA256 in `validation.json`. Main source tests deliberately use only the old 39-observation corpus with admitted raw18/32. The broader 38-frame lower Main corpus exists in the later parent commit `7e5d5eac05a15f682b9f258080cede44ab9f7a18`; this older copied runtime cannot validate its broader Main path. That corpus needs a separate witness export against the newer parent runtime before any broader Main witness result is claimed. V8 direct lower handlers are already owned and are exercised separately here through ClearList, Send/Commit and raw3 source corpora.

Parent integration should run the new Cargo target with both genuine numeric constructor profiles, the existing TLSW1/TLSW2 targets and version-byte tests, all-target Clippy and the full Rust suite. No push or PR is authorized. The parent owns the coherent commit after those gates.
