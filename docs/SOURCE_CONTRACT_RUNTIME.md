# Literal on-chain source contract settlement

`SourceContractRuntime` implements the pinned type18 queue-to-settlement path from JavaScript commit `dca0888b827c5bc28fa9189bc9e1d507f5c5670c`. Call `execute_contract_unverified` with the original nine Types arguments, then `evaluate_queue` with `processQueuedOnChainOrdersForBlock`. Actual Rust Types/Validity, literal Logic flag positions, queue, placement, matching, collateral, margin maps, PnL/IOUs, fee/reward/volume/history writes, oracle publication and reached Insurance deposits operate on the same mutable owner. No validator, match, financial result or post-state is supplied by the test oracle.

This is an explicit alternative to the conserving `EconomicState`, with source Tally documents/cache as its single balance authority. It does not embed another spendable Ledger, copy balances into an economic owner, or silently change `ConservingSequentialV2`. The literal reference permits Number precision loss, stranded reserves, partial writes and retry re-execution; the conserving policies deliberately enforce different invariants. A caller must choose and bind its execution policy rather than combine their balances. This API accepts unverified imported source documents and actor claims. It establishes neither historical chain acceptance nor signature authentication.

## Actual execution

Bootstrap persisted collections through `import_collection`, choose the source module-entry profile with `set_entry`, and configure explicit activation/height boundaries. Supported entries are `main-subgraph`, `types-first`, `tally-first` and `volume-first`; the frozen CommonJS graph has captured partial exports, so the same source fee/volume call can succeed or throw depending on initialization order. Queue documents and instance caches belong to `ContractQueueSourceOwner`; Margin instance/object identities belong to `MarginMapSourceOwner`; every other actual financial collection and Tally cache belong to the runtime. Database, RPC height, UUID, deterministic clock and audit-RNG effects are recorded. The explicit activation, storage and clock boundaries are those of the JavaScript conformance environment, not a production NeDB or authenticated chain adapter.

The runtime reproduces decoded reduce/post/stop argument shifts, reserve oversubscription, self-cross reserve leakage, fixed-eight partial-fill margin strings, seller collateral-call argument omissions, mutable same-block marks, differing settlePNL/realizePnl formulas, fees and rebates, source IOU decimal strings, un-awaited history/reward effects, fee buffering and module-import failures. Fee flushes use reached source Insurance load/deposit/event/snapshot methods, including retained buffers and repeated deposits after partial failure. Cross-reserve recovery uses the same live queue and balance owner, including early cancellation without book save and the source ambient `block` ReferenceError. These are preserved source behaviors, not repaired consensus rules.

A source-thrown exception retains the real prior financial/storage/cache prefix. A local unsupported-domain, capacity or backend error rolls back the candidate. Local admission refusals never masquerade as JavaScript exceptions or supplied successful financial results. Imported malformed Tally JSON keeps the prior cache under the source catch; independently caught cumulative-volume failures continue the remaining reads; JavaScript numeric-key enumeration and signed Number zero remain observable.

## Evidence

`tests/source_contract_runtime.rs` executes all32 scenes/135 observations from the frozen full-module corpus. At every action it compares complete source outcomes, all persisted collections, Tally cache, complete orderbook instances, clearing open/close pools and mark maps, source Oracle cache/watermarks, fee buffer and Insurance instances. It rejects unexpected nonempty collections. Only BigNumber diagnostic text is numerically canonicalized; ordinary strings, serialized stored JSON, Number bits (including negative zero), field order and document order are compared exactly. Fixture states are expected outputs; the runtime consumes only actual bootstrap documents and original actions.

Component suites independently compare109 placement/queue actions, nine reclaim actions using genuine Tally,76 margin actions,27 composed settlement invocations,200 fee-math cases,55 fee/Insurance actions and140 Oracle actions. See `CONTRACT_PLACEMENT_SOURCE.md`, `MARGIN_MAP_SOURCE_OWNER.md`, `CONTRACT_SETTLEMENT_SOURCE.md`, `SOURCE_CONTRACT_FEES.md`, and `SOURCE_CONTRACT_ORACLE.md`. The adapter adversaries cover stale-cache JSON failure, volume read failures, exact thirds in IOU claims, lexical sufficiency and prefixed numeric deltas. JavaScript runs only in these independent test oracles; Rust runtime execution does not invoke Node.

## Remaining gates

This bounded on-chain execution path does not complete the entire orderbook, MarginMap, ContractRegistry or Clearing module. Channel settlement, options/dated expiry, global block funding/ADL/liquidation orchestration, all native/multiple-contract lifecycles, production storage/query equivalence and authenticated input/history remain separate gates. The source financial Decimal domain is finite and resource bounded; nonfinite financial arithmetic is explicitly refused rather than fabricated. Diagnostic Number nonfinites and negative zero are retained where the source produces them. Large malformed/nontransitive V8 sort inputs have an explicit unsupported boundary in the placement owner. Object-identity graphs outside the explicit queue and margin alias capabilities are unsupported.

Replay snapshots re-execute original commands and compare outcomes, effects and actual continuation state; see `SOURCE_CONTRACT_REPLAY.md`. An independently expected replay head is required. Integrity hashes/checksums do not establish signer authority, chain provenance, fraud-proof completeness or historical acceptance. No complete per-transaction fraud-proof witness is exported by this change.
