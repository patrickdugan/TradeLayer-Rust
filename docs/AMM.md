# AMM source behavior and local lifecycle

`src/amm.rs` implements local AMM capital/share accounting, ordered balance-movement journals, contract quotes, inventory/liquidity helpers, option strategy intents, token curve intents, and an in-memory immutable-definition/mutable-state registry. It does not debit the production ledger, execute orderbook trades, authenticate a transaction, or make a durable database write.

The reference is complete, unmodified `src/amm.js` at JS commit `dca0888b827c5bc28fa9189bc9e1d507f5c5670c`. Its LF-normalized SHA256 is `bfb4f5d94c1d4754ae9a17b646c42c4ffe62e077590d0a184ac8ddc0b38255b1`. The exact source is archived in `fixtures/legacy_amm_source.txt`. Unlike IOU/options calculations, every arithmetic operation in this source uses JavaScript Number. Replacing its f64 operations with financial Decimal arithmetic would change the reference behavior.

The pool can be constructed, funded by several addresses, quoted, redeemed partially or fully, snapshotted and reconstructed. Add/redeem operations return the exact successful source balance-call sequence. A contract deposit pledges its property then issues `{id}-LP`; redemption burns that LP then returns the property. Token pairs pledge/issue the first leg before the second, using `{id}-{id2}-LP` and `{id2}-{id}-LP`. Only the **first amount** changes `position` and the address's recorded share. The supplied secondary amount is independently transferred; the source does not record a second reserve/share or enforce a pool ratio. Journals preserve that distinction. They are proposed movements, not funded claims or ledger receipts.

Capital and inventory are different source concepts sharing one `position` field. Constructor inventory need not equal LP shares. Liquidity/curve helpers change inventory without changing shares. `requestLiquidity` tests `position + size` even for sells, so it can reject a reducing sell. Signed sizes and negative curve sizes remain observable. The linear and inverse generators **increase** position by the generated size; they do not consume capital or fill a trade. No change in this module should be interpreted as fixing those economic rules.

Contract quotes retain the source minimum spread of one basis point and zero/NaN spread fallback to 40 basis points. Size is `max(0,min(maxQuoteSize,position))`. Prices use exact ECMAScript `Number.toFixed(8)` then numeric conversion: the binary64 rational is expanded using the existing Decimal engine and rounded half away from zero. This avoids rounding the shortest decimal representation or using Rust's ties-to-even formatting. Exact binary halfway points, signed underflow to zero, subnormals, values above `1e21`, infinities and NaN have independent source vectors. All source initial margin and boolean flags are zero/false; sender and transaction IDs retain their source spellings.

The source permits zero/negative bids when spreads reach/exceed 10000 bps, and nonfinite quotes for nonfinite spreads. The quote helper retains these values for parity. `ContractQuote::validate_executable` is an explicit typed check for positive finite size and price. It does not prove collateral, oracle authenticity, matching priority or transaction authorization.

Option intent conversion `OptionOrder::as_option_position` feeds the existing `options` maintenance/exposure calculators using signed quantities and the calculators' `Call`/`Put` names. This is an explicit Rust integration adapter, not a claim that source AMM strategies open positions. The test exercises the iron fly against existing portfolio maintenance without changing pool state.

Typed state limits are 4096 LPs, 4096 orders and 4096 AMM definitions; metadata fields are at most 8192 bytes, identifiers at most 128 bytes, and blocks at most `2^53-1`. These are local resource/domain restrictions, not established historical protocol limits. Overflow, invalid secondary amounts, duplicate/prototype shares, capacity and registry validation errors leave local state unchanged. Source errors can instead leave mutated pool state or a successful prefix of tally calls; the oracle explicitly records both cases. There is no claim that a returned journal and a future external ledger transaction commit atomically together.

Run `node scripts/amm_vectors.cjs` for the default offline SHA-checked source oracle. `--source PATH` executes a matching external source instead; `--write` regenerates the fixture. No source extraction, rewritten formula or copied replacement AMM is executed. Controlled dependencies record actual tally, orderbook and database calls. The supplied-global token experiment is labeled separately from the ordinary broken entry point. `cargo test --test amm --frozen` checks the numeric vectors and typed lifecycle, integration and rollback properties.

This closes concrete local accounting and calculation gaps. Full AMM execution still requires the authenticated contract/mark boundary, real available/reserve/margin balances and LP property issuance, funded secondary reserves, safe-price checks in the execution path, source-approved repairs to broken methods, production persistence, historical acceptance/reorg vectors, and AMM-first orderbook/clearing integration. No file-level production-parity claim is made.
