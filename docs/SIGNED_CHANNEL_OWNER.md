# Funded signed-channel owner integration (Stage25R V1)

This is the explicitly opt-in `SupersedingCoSignedAllocationV1` policy, implemented inside the existing Ledger, ProtocolState and UnifiedChainState. The channel's actual A/B escrow is the only spendable allocation. Signed transcripts and bootstrap checkpoint bytes are bounded audit evidence; they do not own a second balance.

The base for this staged bundle is TradeLayer-Rust `6403716f4ee77682430d75bba1c22c08a7c85d1b`. The parent has integrated this implementation and completed the actual repository checks recorded below. It does not assert historical JavaScript acceptance, authenticated L1 funding, actor identity, parent-UTXO/script verification, consensus inclusion or L1 revocation. The pure canonical/signature module defines the new domains; the separate complete channels.js diagnostic port preserves source behavior.

## Actual ownership and opt-in

`ProtocolState::with_channel_revision_policies_unverified(self, expected)` attaches an independently configured complete policy table. It cannot replace an enabled table or adopt already-enrolled metadata. Network/genesis and policy keys are checked. Enabling before enrollment is represented in the whole-owner format, so rollback cannot silently discard the expected table.

`UnifiedChainState::from_protocol_with_channel_revision_policies_unverified(state, anchor, admin, history_limit, expected)` moves an actual pre-funded ProtocolState under that table. Its actual finalized height must equal the independent anchor height and its Registry admin must match. V1 therefore requires an explicitly pinned existing bootstrap owner (or pristine height zero); it does not guess a future Ledger hash or mint genesis funds. Independently expected funding outpoints, script digest, participant/key mapping and bootstrap pins are never extracted from candidate bytes as their own authority.

`SignedChannelInput` has `Enroll { txid, channel }` and `Revision(SignedRevision)`. The dedicated Unified method processes authenticated ordinary adapter operations first, the explicit signed inputs next against the actual current parent, and finalizes once. The full owner is staged and its complete checkpoint encodability checked before publishing. A private Protocol encoding preflight retains the *actual prior* finalized height while a block is pending; its bytes are never exposed as a public checkpoint. Finalization is never faked for serialization.

Enrollment's `txid` must equal `ledger::channel_enrollment_replay_id(policy, context)`: SHA256d of the exact bytes `TradeLayer/ChannelEnrollment/v1/ || policy_id[32] || parent_height:u64be || parent_id[32] || height:u64be`. This is a local metadata replay ID, not an authenticated L1 txid. A supplied ordinary/pre-bootstrap/later processed ID cannot replace it. Revisions use the canonical signed body digest as their replay ID. Both paths update the actual Ledger and Protocol global replay domains atomically.

## Fixed funded allocation and fences

Enrollment checks actual distinct A/B owners, complete nonzero per-property escrow, no pending withdrawal or pending NET claim, exact bootstrap parent/network/height, independent actual-bootstrap Ledger hash and independent initial-allocation pin. Applying requires exact successor, previous head, current actual allocation digest, property coverage, checked fixed A+B totals, actual owner context, inclusive valid window and **both** strict low-S signatures under the configured keys. It replaces actual Ledger A/B amounts atomically. Head zero records enrollment and cannot satisfy the signed-current-head consumer.

`channel_revision_head`, `channel_revision_status` and `require_current_signed_channel_head` expose current/superseded/unknown metadata. Current-head checks are immutable relations against the current owner, not transferable spend capabilities. Branch rollback restores status, custody, replay markers, descriptors and signatures together. Older revisions can become current again on a deliberate branch rollback; local supersession never claims cryptographic L1 invalidation.

Private Ledger mutation boundaries fence ChannelCommit, ChannelWithdraw, ChannelTransfer **at both endpoints**, ChannelNetClaim and ChannelKingSettle for enrolled channels. Maturity also refuses any pending withdrawal for an enrolled channel before mutating. Verification/restore enforce the same disjointness, including forged states whose total supply would otherwise conserve. Ordinary unenrolled channel semantics remain unchanged. SpotExchange and FundedIouLedger constructors/verification refuse revision-bearing Ledger imports; the unsupported Chain checkpoint writer refuses them and its legacy decoder rejects the new Ledger version. Existing Economic/Joint channel fences remain intact.

## Complete checkpoint and origin evidence

- TLL versions 1–3 retain their exact canonical output when enrollment metadata is absent. TLLv4 contains complete expected descriptors, deterministic enrollment IDs/context, canonical pre-enrollment Ledger bytes, initial allocation, derived head and full accepted signed journals. The legacy decoder rejects v4; `Ledger::from_snapshot_bytes_with_channel_policies(bytes, expected)` requires independent exact descriptors.
- The bootstrap witness is checked against the independent descriptor hash. It proves the enrollment ID was absent from the actual pinned before-state, actual participants/initial escrow matched, prior processed IDs persist and earlier enrollment/journals are exact prefixes. The witness cannot substitute a later ordinary ID because the enrollment ID is derived. It is not a mutable second Ledger.
- TLPSv3 stores the complete expected table even before enrollment. The policy-aware decoder requires exactly that independently supplied table; it refuses legacy-version downgrade. The global/component replay partition is still checked. Without policies, TLPSv1/v2 bytes remain unchanged.
- TLUCv2 stores all current/prior whole Protocol states with the same independent table and an explicit rollback floor. Earlier enrolled metadata and signed journals must be exact prefixes of later states. Every newly introduced enrollment or journal suffix must belong to that exact block height and parent, and its replay ID must be absent from the before-state; a revision cannot appear retroactively in a later frame. For every retained before→after block, enrollment/revision context parents must match the actual retained parent Tip, not merely its height. Separately valid co-signed branch states with matching supplied heights/IDs cannot be spliced as rollback snapshots.
- The canonical explicit floor is the first retained prior Tip, or current Tip when history is empty. This lets a valid oldest retained state above the original deployment anchor survive rollback/reload and accept a new branch. V1 output and its stricter old decoding rules remain unchanged.

The parent IDs in **pruned** signed contexts remain signed claims: no retained header exists to independently reconstruct that ancestry. The original expected anchor stays separate from the moving rollback floor. Checksums/canonical replay are not best-chain authentication. Independent durable expected head/commitment is needed to reject an older valid checkpoint or ABA restart. The root-owned durable wrapper supplies one Journal owner, exact CAS/poison handling and policy-aware recovery; this owner bundle does not claim those checks from an in-memory copy.

## Resource and failure bounds

Every witness tree uses one scoped validation session with aggregate limits: 8 MiB of traversed/copied witness bytes, 128 enrollment nodes, 4,096 accepted revision records, 100,000 ordinary Ledger records and depth at most 128. These are **whole-tree**, not per-nested-witness reset caps; nested duplication consumes the budget again. Live and decoder counts include every escrow A/B row and each King receipt claim-ID row. A policy-enabled owner uses that same aggregate domain before enrollment, including ordinary-block staging. Blob/count checks occur before retained copies/capacity allocation. The existing 8 MiB revision-metadata and 64 MiB whole-checkpoint limits also apply. Multiple enrollments are supported but nested-history duplication can exhaust the aggregate limits well before 128 current channels; rejection is atomic.

The private decoder structurally parses and validates each child in that same session. Canonical re-encoding uses a private already-validated writer, without invoking public verification/decoding again or caching a serialized trusted flag. Public verification independently checks witnesses and all signatures. Live insertion checks only commit after canonical encodability; ledger invariant errors retain their typed error instead of being collapsed into Capacity. The public codec never publishes pending finalization. No unsafe code or external Rust crate is added.
