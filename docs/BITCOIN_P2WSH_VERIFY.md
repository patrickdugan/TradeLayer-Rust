# Native Bitcoin P2WSH 2-of-2 input verification

`verify_bitcoin_native_two_of_two_input` performs real ECDSA verification for one supported native SegWit-v0 input. Earlier P2WSH and BIP143 audit functions check structure and compute a digest, then explicitly refuse to claim signature verification. This function reuses those exact checks and the existing native secp256k1 implementation, then verifies both actual witness signatures in the actual script's key order.

There is no caller-provided amount, scriptCode, public-key identity, signature verdict or actor. Complete raw funding bytes determine the funding TXID, output amount and P2WSH program. The actual spending input must reference that TXID/output. The actual witness determines the 71-byte `OP_2 PUSH33 key1 PUSH33 key2 OP_2 CHECKMULTISIG` script and two DER signatures. BIP143 commits to the actual selected amount/outpoint, every input outpoint and sequence, all outputs, version and locktime. The private receipt retains immutable borrows of both raw transactions.

The supported profile is explicit: Bitcoin native P2WSH, two distinct compressed script keys, two distinct signature items, empty native scriptSig and CHECKMULTISIG dummy, exact four-item witness, positive funding value, and SIGHASH_ALL byte `01` on both signatures. Flags must equal Core's pre-Taproot consensus mask `0x0e15` (P2SH, DERSIG, NULLDUMMY, CHECKLOCKTIMEVERIFY, CHECKSEQUENCEVERIFY, WITNESS). Unknown or different masks are refused. The fixed template contains no executed CODESEPARATOR, CLTV or CSV. A byte matching an opcode inside a pushed public key remains data.

High-S signatures are accepted because this consensus flag mask does not include the LOW_S policy flag. Strict DER is converted to compact positive R/S scalars, then existing public-input secp256k1 arithmetic checks real signatures. Nonminimal/negative DER, zero/out-of-range scalars, off-curve keys and signatures for the wrong digest/key are rejected. Fixed 2-of-2 CHECKMULTISIG requires signature1/key1 and signature2/key2; swapping signatures cannot bypass that order.

This is a deliberately bounded input-template verifier. Unsupported cases are refusals, even where generic Core Script would accept them. They include other native witness templates, legacy or nested P2SH, uncompressed/duplicate script keys, identical signature items, zero-valued funding in the reused structural profile, other sighash modes and flag sets, Taproot, MWEB and AuxPoW. It is not a general Script interpreter or a repair to the pinned JavaScript policy.

No Core business body is changed. Reference bindings use their published FFI; the proposed native implementation has no new dependency, unsafe code or build script.

The deterministic TSV contains 57 executed reference cases: 10 accepted by the native supported profile, 20 accepted by Core's input checker and 37 rejected by Core. All 10 native accepts are genuine Core accepts. The other 10 Core accepts are explicitly outside this profile or its separate raw-funding binding: valid unknown sighash bits, zero funding, requested funding-vout mismatch (Core receives only a script/amount), missing WITNESS flag, duplicate keys, identical signature items, uncompressed keys, OP_TRUE witness script and two published non-2-of-2 Script cases. Such refusals are not reported as Core invalidity.

Four fixtures directly reproduce published Core vectors at JSON indices 1013, 1014, 1108 and 1109 using Core's exact crediting/spending transaction layout. They test the reference's actual invalid-script/hash-mismatch and valid P2WSH/P2WPKH outcomes and our explicit unsupported-template boundary. The existing independently OpenSSL-verified genuine two-signature fixture retains its exact BIP143 digest `35e95e9e4200ab42a0bb2470a1528f4c32c898800b49dba080d551855ed4e4f0` and high-S acceptance. Remaining public throwaway fixtures cover key/signature order, multi-input selected positions, wrong amount/outpoint/script/output/sequence/version/locktime, both bad signature slots, malformed DER, zero/overflow scalars, off-curve keys, malformed witnesses and unsupported flags/hash modes.

Three new Rust tests passed in isolated Rust 1.90 debug and release runs, along with the two unchanged SHA tests. Test and production Clippy with warnings denied and formatting checks passed. Replacing only actual ECDSA verification with unconditional success makes the focused gap-closure test fail. The unchanged digest-only API still accepts structurally plausible wrong signatures and denies authority; the new function rejects their real mathematical signatures. The independent Core executable, exact source/archive provenance, byte-stable generator, outcomes and command logs remain frozen in the work-stage evidence.

## Remaining authentication boundary

Success proves the supported selected-input script/signature relation to the supplied exact raw funding/spending bytes. It does not prove that the funding transaction was valid, mined, active-chain included, mature or still unspent. It does not verify any other input, transaction value conservation/fees, finality, active rule deployment, block inclusion or chain consensus. One positive case deliberately has an invalid other-input witness; selected-input verification succeeds and complete-transaction authority still refuses.

Every receipt permanently refuses authenticated parent-UTXO, complete transaction/chain consensus and TradeLayer actor/economic admission. No trusted adapter, node follower, Ledger owner, policy version, checkpoint format or admission gate changes. Default V2 and old policies/formats remain untouched. Stage25Q transcript signatures and Stage25R sole-Ledger ownership remain separate from this L1 input verifier. A future full adapter must bind these exact bytes to independently authenticated chain/UTXO/rule context and to the actual TradeLayer actor and operation before admitting anything.

For integration, add the module declaration and copy the source, integration test and TSV. The new module reuses existing private Cursor/DER helpers, existing BIP143 and public secp256k1 APIs. Root must compile/test against its actual current crate before committing; isolated tests used immutable Core library `60ec139e80f8991ab1c065c55f7244f6b38c8f54d849d68ebd5a684e7f9d7c8a` and unchanged private audit-source copies only for module visibility.
