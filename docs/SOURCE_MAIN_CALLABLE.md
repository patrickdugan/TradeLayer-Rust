# Main callable source profile

This stage adds `MainCallableV8` over the same literal source Core, queues, Tally, Margin objects and collections. Both focused Main tests now pass against the actual Rust1.90 MSVC V8 library through an independently linked test executable. Parent-owned Cargo/full validation remains separate. The unchanged-class Node evidence is recorded in `MAIN_PHASE_DRIVER_EVIDENCE.md`; those 39 observations do not establish 39 Rust comparisons.

The callable surface is `Main.processTxSet`, `Main.processTx`, `Main.blockHandlerMid`, `Main.loadMaxProcessedHeight`, `Main.saveMaxProcessedHeight`, `Main.loadTrackHeight` and `Main.saveTrackHeight`. Main's two transaction loops reuse the runtime's actual Types decoder and Logic dispatch. Successful and failed processed-row writes and the first matching `txIndex` validity row use the same Core database. An ordinary source exception retains its completed metadata and financial prefix. A local unsupported-domain or capacity error restores the complete runtime, including effects, failure schedule and temporary object origins.

The initial Main transaction composition admits original raw types 18 and 32, ASCII bounded payloads and ordinary string transaction IDs. It does not admit error-valued decoded objects or general aliased/getter/proxy/function graphs. Other already implemented raw transactions retain their standalone public entry points; this Main profile refuses their composition until it has genuine phase observations. Finite nonnegative integral block heights are required for the selected mid phase. `constructConsensusFromIndex`, block begin/end, daemon import, persistence startup, RPC, activation initialization/activation and reorganization remain unavailable. Refused phases do not return an invented success.

`blockHandlerMid` invokes the actual fee flush, liquidity reward settlement, on-chain queue drain, channel queue drain, clearing and withdrawal helpers in the original order. Its initial supported continuation profile requires empty preexisting fee and liquidity reward buffers. The queue itself can be populated by the actual transaction processing in that same call. The source's unawaited maximum-height write starts its genuine database factory before phase execution; a bounded continuation runs its update at the observed next factory/empty-buffer suspension. Its caught observer rejection is retained in the explicit Main state and ordered effects. This is the completed-drain scheduling profile proved by the finite Node observations, not a general JavaScript event-loop or process-liveness claim.

V8 activation has one explicit entry profile. The default `source-registry` routes every Activation read to the same existing `SourceActivation` owner and the Core's `activations` collection; Main requires this profile. The standalone `declared-answer` profile preserves an explicitly declared external activation answer for focused source-boundary corpora. Select it with synchronous `SourceMain.configure({activationProfile:'declared-answer'})` before the first accepted Activation/Main use. That use locks the profile; changing it afterward is a local error without effects. Main calls locally refuse the declared-answer profile. The selected profile, lock, actual activation cache/action counter and deferred height state are replay-bound V8 state. The legacy `set_activation_answer` field is ignored as an authority in the source-registry profile. A future witness descriptor must name this entry profile explicitly.

The staged two tests request 18 admitted method comparisons, 13 constructor-prestate resets and seven explicit unavailable-phase refusals from the original 39 Node observations (the separate full-import observation has no Rust invocation). They compare outcomes/transports, all collection rows, actual receiver caches, every live Margin instance, queue receivers, position-context contents, ordered database/phase effects, failure prefixes and retry history. Map/Set values are observed as ordered arrays; the fixed source `/^tx/` query is transported through the existing anchored-literal DB capability. Other regular expressions only remain diagnostic evidence for the refused catch-up calls. Neither this fixture adapter nor those projections claim production NeDB or compact-store durability.

The second test also requests independent-head restore, canonical re-encoding, corruption rejection, profile locking, unavailable-phase rollback and V1–V7 method isolation. The stage introduces TLCR8/bootstrap v8 without changing existing policy bytes. Replay detects substituted commands/state relative to an independently expected head. It does not establish actor authorization, transaction inclusion, chainwork, bootstrap truth or custody authority.

The resumed exact-state comparison corrected two observer errors rather than weakening assertions: original RegExp values use the Core's complete `$regexp`/`$flags` diagnostic fields, and the original Orderbook loader registers every actual receiver, including the fresh liquidation-prune receiver omitted by the earlier selected-method observer. All real receivers, states, argument fields and ordered effects remain compared. The two tests pass with cached actual V8 library SHA-256 `0ba1e560422f7c2cbba1f08ee31b2bf1783a7cd0162a5e265c7517428a89df1e`; the test-only link used Rust1.90.0 and completed both tests in 12.84 seconds. No library was recompiled by this worker.
