## 1. Receipt wire contract (research v1)
receipt.cjs provides fixed-width canonical bytes, SHA256 tagged conversion digest and asset-side HTLC nullifier, BIP340 public verification reference and three-party verification. Dedicated receipt signing keys must be bound to actual channel peers in a separately authenticated context. The edge's position in immutable funding-peer order is registered separately from signing keys; never sort rotating signing keys to define an HTLC identity. The outpoint format is display-order txid bytes then u32 BE output index. All u64 are BE; external quantities are canonical decimal strings. The two directions must have opposite transfer directions on their legs.

Byte order: version u8=1; thirteen 32-byte fields (genesis, policy hash, asset id, edge x-only key, BTC peer x-only key, asset peer x-only key, full RFQ id, request/accept transcript commitment, payment hash, asset pre/post commitments, BTC pre/post commitments); direction u8 (0 purchase by edge; 1 sale by edge); asset edge side u8; BTC edge side u8; asset outpoint 36B, offerer u8, HTLC id u64; BTC outpoint 36B, offerer u8, HTLC id u64; asset atoms u64; gross BTC msat u64. Total 526 bytes. Tags in source are normative for this experimental version. Each role signs the same tagged digest, with a reviewed signer. The nullifier includes genesis + canonical asset outpoint + immutable offerer side + HTLC ID only. No epoch, policy, receipt key, quote or amount salt. Keep nullifiers global across index epochs. Reject unresolved funding/splice identity. Tier-1 return has eligibleForIndex=false even with all three valid signatures.

The bundled variable-time BIP340 verifier is a reference for tests, not production crypto. Do not reuse fixture signing code for any real key. Cross-check full official BIP340 vector suite and a reviewed secp256k1 implementation; extend boundary negatives (bad point, r>=p, s>=n, infinity, odd-y result) before circuit work. Freeze exact encoding digest/nullifier fixtures from independently implemented encoder. Wire-format changes require a version bump.
